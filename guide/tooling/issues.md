# Issues
Issues are used to track issues and tasks in a project. They can have labels, relationships and linked pull requests.
PLEASE! use these features, it makes the project management a lot cleaner and allows for much more elaborate filtering.
Always make sure to assign something to yourself if you are working on it and mark the status as "In Progress" whenever you are working on it actively.
Also always move it back to "Stale" when you aren't working on it anymore.

Furthermore, use subissues whenever possible, which allows us to see progress for the task in the project.

Finally, **open issues in the repo they concern**. This means that blog issues or tasks should be opened in the `blog` repo, backend issues in the `backend` repo, etc.
If you find a bug with a part of the software that someone else has written,
open an issue in the repo using the appropriate template and assign the person responsible for that part of the code.
You can find out who is responsible for the feature using `git blame` or the webui on GitHub.
